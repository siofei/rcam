# ADR 0005：S0-C 冻结 EditableV1-Core 目标范围

日期 2026-09-15；基线 1.1 的 S0-C 范围补充，schema_version=2 不变。
授权依据：用户要求依据 `RCam_S0C_S1_Development_Guide.docx` 执行下一阶段。
状态：**实施目标已冻结；产品尚不授予 EditableV1-Core；S0-C 退出因 Windows 原生证据阻塞。**
取代 ADR 0004 的“尚未授权研究范围”结论，保留其历史审计及未通过记录。

阶段 S0-C；R01/R03/R04/R05/R06/R14/R18/R19/R20/R21/R22。
关联 AT-001/003/004/006–019/053/055–057/080/081/085/088/095。
允许改动：审计/证据脚本、公开合成样本、服务边界测试、设计/用例/能力/阶段文档和源码清单。
本轮无产品语义、writer、GUI 或依赖扩展。S1 目标独立登记，不能用范围冻结冒充实现。

“成像次数”包括 Region 内的边操作，不等于最终对象数量；审计不计算制造几何或往返成功率。
CORE-04 的矩形绘制独立按源坐标差检查：3856 条垂直、2336 条水平，无零长度/斜线/矩形圆弧。
这是指导文档原表未列出的**新增必需能力**，不能继续以“非圆 D01 一律拒绝”满足 CORE10。

宏实际表达式包括变量赋值及乘/除/减；未用定义仍完整记录，不能用最后一次定义覆盖先前非法使用。

## 目标支持清单与当前实现的区别

下表均为未来语义、编辑和 writer 的共同要求。当前 S0 仍只开放已有有限圆 Flash，
新语义输入必须拒绝且不新增文档；scope boundary 测试据此检查，并不将拒绝计作未来支持通过。

| 特性 | 冻结目标与拒绝边界 | 回归文件（fixtures/synthetic/s0c） |
|---|---|---|
| 基础标准子集 | 保留设计 4.1 的 C/R/O/P、圆 D01/G75、Region、曝光/局部孔、LM/LR/LS | 原 F_* 用例 + g75、region |
| AM | primitive 1/4/21；有限常量、变量、赋值及 +/−/×/÷ 表达式、旋转；局部 Dark/Clear 顺序；超限/除零/非法轮廓拒绝，其他 primitive 仍拒绝 | am_1、am_4、am_21_variables |
| G74 | 单象限解析为真实圆弧；圆心候选/方向/同端点与量化合法性均需独立断言 | g74 |
| 增量模式 | FS I/G91 实际成像必须支持；转为绝对毫米后编辑/输出；省略轴是零增量，I/J 仍是圆心相对量 | fs_dix34y34 |
| 旧 FS | CORE10 的 4.5/4.4/3.4/2.6/3.5/2.5/4.3；L/T 按声明补零；CORE 的 D 仅全宽整数数字子集，位数不符/小数点/冲突声明拒绝 | fs_*；原 AT-006 保留 T 覆盖 |
| 矩形光圈 G01 | 无孔、未变换 R，水平/垂直非零线段，按真实矩形扫掠规范化；其他非圆扫掠仍拒绝，不用圆端帽替代 | rectangular_draw |
| SR | 只接受 X1/Y1/I0/J0 及结束语句，验证作用域后规范化；其他重复仍拒绝 | sr_identity |
| IR/IP/OF/MI/SF | 只纳入 IR0、IPPOS、OF0、MI0、SF1；按数值和合法位置校验，不能做字符串删除 | legacy_identity |
| G54/G71/IN/LN | G54 必须关联有效 DCode，G71 与显式单位一致；IN/LN 作为源元数据登记，按保存元数据策略报告，不复用为稳定 ID | legacy_identity |
| IC | 只纳入前置 ICAS，校验实际编码；其他编码拒绝，不对文件进行猜测性解码 | ic_ascii |
| IO | 纳入前置、显式单位、A/B 有限偏移，应用于图像坐标一次；与 OF/变换组合未证明者拒绝。非零 IO 绝不能忽略 | io_nonzero |
| AB/复杂 SR/其他宏/其他旧变换 | 保持明确拒绝，全文件扫描且禁止加工输出 | AT-019 原拒绝集 + S0-C 正反边界 |

S1 的资源目标须至少覆盖冻结 CORE10 最大 4,961,139 字节与 230,409 次 Flash，
并在读入/展开/验证/历史分别计预算；此处不擅自增大原型常量或降低性能门槛。
每项只有 ParseSupported、SemanticSupported、EditRoundTripSafe 都有证据才可授予文件能力；
支持矩阵按整个文件的特性交集判断，不能把一条宏支持当作整文件可编辑。

## IO/IC/FSD 的依据与剩余验证

[Ucamco 2026.05](https://www.ucamco.com/files/downloads/file_en/554/gerber-layer-format-specification-revision-2026-05_en.pdf)
第 4.5、8.1.10、8.2 涉及宏、G74、旧 FS/增量；IO/IC 不能仅凭当前规范目录推断。
[gerbv 自身源码](https://raw.githubusercontent.com/gerbv/gerbv/b941a4a562f99127684198658dcd22d97c530d0c/src/gerber.c)
明确区分 IO 图像偏移、IC 输入编码和 FS 的 D 分支。已固定调查源码 commit `b941a4a562f99127684198658dcd22d97c530d0c`，不是新增产品依赖。
首次沙箱下载失败、首次 master API 查询返回422；随后查询实际默认分支完成归档。
2026.05 PDF SHA-256 为 `ac9e9899f573d69e472b2112f1ae879c70f6cd13e17db41a1c885caf69961662`；
源码/规范保存在本轮 references，其 manifest 记录哈希。完整2024.05/2026.05差异审查仍未完成。

实际调用本地独立 gerbv：路径 /opt/homebrew/Cellar/gerbv/2.11.1/bin/gerbv，
自报 version v4.0（与目录版本不同，按原始日志保留），二进制 SHA-256
`fe0d337aa07163b847cfe78784dfefe0627e4a6516db4c025b11cc8eb03c8383`。
使用自编无私有信息的输入，固定视口导出 SVG，对照显式目标几何：
IO 在 mm/in 两种单位下与加偏移后的中心一致；ICAS 与同一 ASCII 输入一致；
FSDI/G91 两次 Flash 与绝对中心 (1,1)/(2,1) mm 一致。4 对输出逐字节相同且非空。
这是独立工具的**有限合成对照**，不从 SVG 回写模型，不等于 CORE10 制造几何或独立完整往返验证。
执行脚本 `scripts/check_s0c_reference.py`；原始输出见本轮 reference-pairs。

IO 与 FSD 的完整真实文件输出、复杂组合和保存规范化仍需 S1 语义回归验证；
没有这些证据，产品保持拒绝。独立工具只在开发机外部进程运行，不进入产品依赖或发行包。

## 验收变更控制

新增范围附加到原 AT-006/008/010–019/053/055/057/080/081/095，
完整操作、数值断言、异常零修改、独立工具及往返要求见 acceptance_cases.json 的 s0c_scope_extension。
保留所有旧用例步骤、阈值、96 个有效身份、185 个逐平台槽和 AT-079 退役记录。
AT-019 的“已升级特征必须有新增完整用例”通过上述逐项补充场景兑现；不再要求未来已获证的
限定子集也必须拒绝，但当前实现未获证时仍必须拒绝。不能只添加一条成功解析测试。

## 退出决策

本机可完成：10/10 使用审计、18 个公开回归输入、范围冻结、独立有限对照、现有服务边界回归。
Windows 原生构建/测试/release 启动与 GPU 信息仍阻塞，不宣称 S0-C 或双平台通过。
不在本轮进入 S1。下一轮按指南先实现目标子集语义/writer，再打通 Move/Undo/Redo/安全另存/重开，
且正式切换前必须取得 Windows 基线；只缺硬件时可进行独立核心开发，但阶段标签仍是阻塞。
