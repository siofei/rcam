# ADR0063: prepare host artifacts before draft publication

Status: implementation in progress, following independently accepted bounded cb9 and frozen 8a backend; no native or full-stage PASS. S5/P3 UE-A, R05/R09/R10/R11/R12/R16/R17/R18/R21/R22; compatibility AT-030/031/034/035/036/037/038/039/040/041/043/064/065/066/067/078/086/089/090/093. Modules: editor-core/edit, editor-service and editor-app, synthetic tests and contracts.

The trusted host can prepare display and working Snap artifacts from a borrowed prospective manufacturing candidate. The candidate identifies each geometry by the authoritative original layer/object slot; it is never writable and cannot supply replacement geometry. Existing APIs retain their behavior through a no-op preparation callback. Preview, Execute, Apply and internal Undo/Redo/Reset run preparation after calculation, validation and admission, before one publication barrier. Preparation or cancellation failure preserves work, internal histories, main history and the previous artifacts. Successful accepted parameter input may already have advanced the input generation; that generation is distinct from published work.

The GUI uses one existing worker/service, an independent session identity and serialized admitted requests. Working snapshots preserve complete source exposure order, definitions and object metadata; entry reference is decoration excluded from manufacturing, hit testing and Snap. Host snapshots/scenes/indexes and their old/candidate coexistence require separate explicit resource admission; the backend 64 MiB charge is not a whole UI/RSS promise. Final Apply includes current unexecuted typed input, returns explicit Changed/NoChange and installs prepared artifacts without fallible postcommit geometry preparation. TooLate waits for the real terminal. Existing numeric tools, Snap/Alt, shader, trajectory and native acceptance gates remain unchanged.

CPU additions: authoritative target mapping with reversed group order, host preparation refusal before each publication path, cancellation after preparation and before barrier, exact Undo/Redo/Reset checkpoint invariants, Apply refusal preserving ticket retry/history, and no-change preparation/terminal behavior. GUI ownership, display/Snap, rectangles/IME and fresh native candidate gates are required before UI closeout.
