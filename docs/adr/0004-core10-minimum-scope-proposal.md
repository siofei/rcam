# ADR 0004：冻结 CORE10 的最小范围扩展提案

状态：提案，未批准扩大 Gerber 支持；S0 退出仍阻塞。
日期：2026-09-15；阶段 S0-B；R01/R03/R04/R05/R06/R19/R21/R22；AT-008/009/020/070/081/085/095 前置检查。

## 实际审计与局限

在此前授权的本地目录只读处理原 manifest 中 CORE10，10 份源哈希在处理前后均匹配冻结值，未换样。
使用可交付脚本 `scripts/audit_core10.py` 逐字符分隔普通/扩展命令，完整保留 AM 块，逐条记录偏移、
光圈选择、D 操作、插补/G74/G75、Region、极性和 SR 上下文；没有调用产品 parser 冒充兼容。
所有原始 token、光圈名称/参数、源路径和源文件哈希留在被忽略的私有 evidence 目录。
公开测试 `scripts/test_audit_core10.py` 覆盖多命令块、零前缀 DCode、未用宏、Region、模态 Flash、
数字形式不同的恒等候选和未知命令拒绝。此审计统计使用关系，不计算真实制造几何。

这里“无”仅表示扫描器能分类，不表示语义正确/可编辑。所有光圈定义均被选择；另分别记录
“已选择但未参与非 Region 成像”的情况。CORE-06 有三个完全未用的 AM 定义，不能将宏出现次数

首次审计保留两个工具问题的输出：零前缀 ADD 被误当作另一个 DCode；十进制零/一被字符串比较
误判为非恒等。脚本修正并以构造测试验证后重新运行，没有改真实样本或删除早期结果。
最终退出 1：CORE-04 的 IO 与 CORE-08 的 IC 尚未解释；不能把剩余八份 audited 状态计作 AT 通过。

## 最小提案与进入实现前的条件

1. AM：仅先研究实际使用的 primitive 1/4/21（圆、轮廓、中心矩形），以及这些实例需要的有限变量、
   赋值、加减/乘除和旋转。冻结参数约束、局部曝光与边界预算；不推断已支持任意宏。
   未用 AM 仍应完整扫描、保留诊断并受预算约束，不能为通过而静默跳过未知语法。
2. G74：CORE-08 是实际依赖，需独立验证单象限圆心候选选择、方向、跨轴边界、退化/歧义拒绝，
   保留 f64 圆弧及量化后合法性。CORE-06 的模式设置仅作状态记录，不虚增圆弧需求。
3. SR：CORE-04 当前仅发现 1×1、零步距形式；先提出该确切恒等形式/作用域处理，其他阵列继续拒绝。
   不能把这个发现当作整个 REAL30 或用户全部样本无复杂 SR 的结论。
4. 旧命令：IR0、IPPOS、零 OF/MI、单位 SF 均是数值上的恒等候选（包括 0.00000/1.00000 写法）。
   先核对固定规范的作用域和与单位/坐标的先后关系，再决定规范化方式；不是直接白名单忽略。
   G54、G71、IN/LN 也需要明确状态/元数据政策。
5. 额外阻塞：CORE-04 有非零参数 IO；CORE-08 有 IC、FS 的 D/I 修饰及 G91 增量模式。
   当前 V1 明确排除增量模式，不能用“恒等旧命令”覆盖这些特征。需要规范/生成器资料和独立工具核对；
   无法证明正确时整个文件继续拒绝。部分核心文件还有 3 位小数等旧 FS，需冻结相关旧格式解释。
6. 真实尺度：CORE-02 命令数量很大，必须据实际源/对象峰值冻结 S1 总预算，不能靠扩大 GPU 的固定数组，
   也不能用当前 2 MiB/100,000 原型上限宣称核心样本最终适用。

上述是最小研究范围，不是已批准实施范围。需要对应 DESIGN_V1 支持矩阵、ACCEPTANCE_V1、机器用例、
规范差异记录和独立真值同时修订，保留原用例/阈值/CORE10 身份，才可开始后续语义实现。
本轮不修改 96 个有效 AT 的初始执行状态，不进入 S1，不启用生产导出。
