# ADR 0042 — S4-D1 PCB / PnP / RefDes Foundation

Accepted 2026-09-30; Mac-first bounded acceptance completed 2026-10-01. Final identity: versioned exports review.

ComponentPlacement is independent of SemanticDocument. Board state owns a detached component table, explicit source mapping/provenance and optional Board→World registration. Coordinates are bounded f64 mm; rigid registration applies local X reflection, CCW rotation, translation, never scale/shear. Bottom uses the same Board frame; no inferred Bottom reflection. Source unit, rotation sign/offset, Y inversion and exact Top/Bottom tokens are explicit input choices.

Schema strategy: preserve v1 encoding for board=None. Projects with Board state use version 2 in both project.json and manifest.json. The new reader supports v1/v2; v1 empty board placeholder migrates to None; nonempty v1 board is rejected. Old readers reject version 2 before loading. Geometry encoding and compressed ZIP safety budgets remain unchanged. Board validation is mandatory for encode/decode, including unique IDs and (Side,RefDes), finite bounded coordinates, mapping/provenance limits, registration numerical proofs and checked component budgets.

Project metadata transactions share the existing chronological bounded history as a distinct Board operation, with immutable before/after snapshots and state guards. They do not masquerade as layer operations and do not mutate SemanticDocument. The service's monotonic revision fences all content edits including Board; manufacturing dirty is still geometry-hash based. Project dirty includes Board. Undo/Redo restore exact Board state, advance revision and interleave with existing geometry edits. Search/focus/overlay stay session-only, outside dirty/history.

PnP v1 replaces the component table only after explicit preview and whole-batch validation. Existing nonempty data requires allow_replace. IDs use a monotonic session allocator, seeded on Open, never rewound by Undo. File policy and bounded reading precede parsing, no filesystem work occurs inside the transaction. CSV/TSV UTF-8/BOM with quoted delimiters/newlines/escaped quotes; header indices are explicit and distinct. No guessed column mapping or side/units. Errors expose physical line and field/category only, never raw private values.

Frozen budgets: 32 MiB input, 100,000 components, 200,001 physical lines, 32 columns, 1,024 UTF-8 bytes per field, 100 displayed diagnostics, 1e6 mm absolute Board/World coordinates; query text 128 bytes, page <=500. Release synthetic 100k benchmark passed without lowering thresholds. Two-point registration baseline >=0.001 mm, absolute distance mismatch <=0.001 mm, endpoint residual <=0.001 mm; these are registration fit checks, not changed manufacturing tolerance. Manual/Identity calibration requires explicit confirmation. Unknown registration is shown as uncalibrated and refuses focus.

No new dependencies. Parsing uses Rust stdlib and existing serde; virtualized list uses locked egui ScrollArea::show_rows. Diagnostics log only counts/category codes, no RefDes/Footprint/Value/source text/absolute paths. Import parsing/search run on existing worker, late results are fenced. Stage stops before S4-D2 association, replacement, Drill, assembly export or Windows acceptance.

Clean candidate d06f653 macOS release measurement: 100,000 synthetic components / 2,917,931 input bytes; preview 113.711 ms; import 203.193 ms; exact/prefix/substring 1.009/0.924/1.121 ms; list 1.075 ms; virtual index 2.444 ms; document-info dirty hash 124.929 ms measured separately; actual process peak RSS 112,148,480 bytes. Thresholds remain import/preview 5 s, query/list 100 ms, RSS 512 MiB. Final rerun values belong to the versioned exports evidence. Category metrics use the retained first 100 diagnostics alongside the full diagnostic count.
