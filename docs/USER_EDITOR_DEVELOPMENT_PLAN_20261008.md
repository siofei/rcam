## 2. 统一图形编辑器：已确认交互契约

### 2.1 一个窗口、入口几何与工作几何

- 集中一个编辑窗口，支持跨层多选；保留各层独立的制造曝光语义和权限检查。
- 进入时固定入口几何为参考底层，只在窗口会话内存在，不可选择、不可编辑；整个会话不随步骤更新。参考拾点/Snap 是否允许及其独立交互标识须在实现设计中明确，不混入制造对象索引。
- 工作几何逐步累积：执行 `+0.1 mm` 后再执行 `+0.2 mm` 得到 `+0.3 mm`。同一步参数输入预览从该步执行前的工作几何重算，不能每击键再累加。
- 每次“执行本步”加入窗口内部 Undo/Redo。复原清除本次全部步骤并恢复入口形状，窗口保持打开。
- 最终应用经服务一次原子事务提交并退出；主画布能一次 Undo 撤回整个会话，跨层结果一致。
- Cancel/关闭时若有未应用工作变化，提示丢弃。最终应用时存在未执行预览，必须明确处理；建议要求先执行，或明确选择仅应用已执行步骤，不静默丢弃或重复累加。此默认处置尚需确认。
- “应用到所有选中”仅作用于本次操作，不延续到下一步；步骤参数、范围和失败策略作为独立操作记录。

### 2.2 缩放与四方向尺寸

- 2026-10-09 用户新增键盘视图缩放：默认可改 PgUp 放大／PgDn 缩小，基于当前比例乘／除同一可持久设置系数 k。默认系数与锚点待统一现有导航设计；验收与范围见 §19，本次仅计划。

- 面积比例缩放支持几何中心与面积重心。此处几何中心明确为制造包围盒中心；面积重心扣除孔洞，零面积/无法确定时明确拒绝，不能偷换为包围盒中心。
- 四方向绝对尺寸增减不强制保中心，按各边指定值改变边界。
- 四方向百分比以上一步执行后的当前 W/H 为基准：上下各 `+5%` 得到原当前高度的 `110%`，不是连续两次 `105%` 的复合。
- 可简化为上下/左右两值，提供上下互换、左右互换按钮；毫米量与百分比的参数语义和基准在图解中显示。
- 对跨层组合，几何/面积组合中心定义及选择作用域须可见；不同层的制造覆盖不能合为会相互擦除的单层图像。

### 2.3 内缩、圆角、斜角与失败策略

- 轮廓内缩：外边向内、孔边向外。分裂后保留所有片；完全消失判为失败，提示原因且不修改该对象。
- 圆角/斜角可批量作用所有选中图形；任一角的参数不能实现时，整对象失败，不留下部分角修改。
- 用户可选择失败对象保持原样或删除；先显示失败数量及原因，删除需明确作用于失败对象。最后提交仍是整体一次事务，提交失败保持原状态。
- 圆角使用 R；斜角使用两边距离。两边距离默认联动为已接受建议，可解除联动。
- 必须验证孔洞、窄缝、自交、退化、凹角、圆弧连接、分裂和消失，不能从 GPU 网格或显示细分反推制造几何。

### 2.4 防锡珠与参数镜像

- 防锡珠包含凸三角、凹三角、梯形、U 等方案，图解深度、宽度、方向及绝对值/百分比参数。
- “凸三角”可能是原边界内的角切尖，不能默认解释为向外附加三角形。相关图示语义待实际像素核验，明确切除/增加方向后再实现。
- 参数来源为当前编辑焊盘的任意指定位置；支持左右、上下镜像参数。
- 恰好选中两个对象时自动以另一对象为目标；多对象时由用户点目标。目标保留自身尺寸，镜像的是操作参数：源左 `+0.2 mm` 对应目标右 `+0.2 mm`。
- 默认只镜像本步，也可选择完整的有序操作序列。重复应用同一步到同一目标不能意外累加；需稳定步骤身份和执行前基准。

### 2.5 基点、拾点与防误触

- 所有适用操作支持自定义基点、几何/面积中心快速取得、多层组合中心、轮廓拾点，以及移动过程中的轮廓 Snap。
- 复用现有适用输入/Snap/Alt/取消路径，补缺口而非将已有实现重复记为未做。
- 用户已确认 canvas 小十字显示尺寸为当前的 3 倍：以实际未裁剪每轴 12 physical px 为基线，目标 36 physical px（half=18/ppp），维持 DPI 一致、中心/世界坐标/命中与 Snap 阈值不变，大十字模式不变。只改显示，独立实现与端点/裁剪/模式隔离回归，不混入阵列冻结候选。
- 鼠标移动、鼠标改形分别开关；小/大十字可选。会话原参考、当前工作几何和实际拾点目标视觉区分，不能误编辑参考底层。
- 用户已确认设置提供“选中 Block/Aperture 时显示基点”，默认开启。该设置仅影响选中实例的辅助显示，不改变制造数据；作为显示偏好与几何操作命令区分，未来宏不得把显示标记当作可制造对象或隐式变换。
- 基点语义按实际实例插入点/定义原点经实例 transform 后的世界坐标设计，不混用包围盒中心或材料面积中心。多选适用实例、旋转/镜像与嵌套坐标链、密集可读性/裁剪、标记样式与命中/Snap 参与规则列为后续设计和测试；用户确认范围是选中显示、设置入口及默认开启。

### 2.6 启动命令后跟随鼠标、点击完成的移动

- 用户明确移动交互为“启动移动命令 → 跟随鼠标预览 → 点击目标完成”，无需一直按住。新增明确命令模式；旧按住拖动入口可保留为独立模式，不擅自删掉。当前 `OBJECT_MOVE` 是参数/点输入窗口入口，尚不等于该完整命令模式。
- 明确基点与目标点：基点需来自已有定义基点/自定义拾点/材料中心等已确认语义，目标可鼠标、数值或已有 Snap/Alt；先锁定完整选择、文档/工作区/权限版本，再以目标减基点形成真实 delta，不能把零 delta 校验准备当成移动结果。建议 Esc 取消与现有点会话一致，取消零修改。
- 跟随期间只有可撤销预览；一次点击最多一个原子 commit、一次主 Undo，不因重复鼠标事件/双击/迟到回复提交两次。连续移动、目标点击后是否自动退出或再次启动、失焦/PointerGone/工具切换、等待中取消和未保存工程保护需明确并回归；焦点丢失不得隐式落点。移动宏记录选择绑定、基点、目标/位移、单位、版本与终态，不能记录依赖未锁定鼠标状态的动作。

## 3. 条件选择、同定义选择与类型锁

- 条件选择支持面积、周长、间距；字段单位及边界包含方式明确。
- 间距有两种模式：相邻满足条件形成组；同一组内任意两成员均满足条件。不能把连通链 `A-B-C` 自动当作组内两两满足。
- 邻接距离的制造边界/中心口径、同层或跨层作用域、Dark/Clear 后最终可见覆盖与源对象几何的关系，需在接口设计中确认。
- 选择同 Aperture/Block：以当前所选有效 Aperture/Block 实例的真实定义集合为种子，目标图层仅为这些种子所在的可视可选层；在目标层内选择匹配任一真实定义／类型且通过原有锁和准入过滤的对象。多定义取并集去重，单选仅扩展其源层；top+bot 种子不扩展第三层，普通图形不贡献定义或目标层。跨层同形但不同定义不自动等价。快捷键、右键、快捷入口和宏共用此作用域，详见 §20。
- 层内类型锁按原始定义身份，不能按变形后外观或当前几何分类偷偷重新归类。导入定义、写时复制新定义、转换和定义修改时的身份延续规则需设计。
- 显示分类开关、同定义选择、类型锁是不同概念；不能把当前 `DisplayClass` 当成所有新功能的定义身份。

### 3.1 单击邻近图形与稳定循环选择

- 用户已确认点选改进：图形内部可命中，图形外点击也可在一定范围选取最近图形；同一有限范围内连续点击可循环选择。默认邻近范围和位置重复容差尚未定，不做全画布无界最近查询。
- 现有 I1 并非零实现：`ClickContext` 用当前 6 physical px 的 camera tolerance 查询真实命中候选，`Model::canvas_select` 按可见可选层与逆对象曝光顺序循环，去重完整文字组；相同位置目前为距固定首击锚点 ≤2 physical px，并绑定 camera/rect/ppp/navigation epoch、文档/内容/工作区修订和有序候选。已有 holes/凹形/容差/跨层与循环重置用例，但这不足以宣称新需求已完成：当前没有以实际轮廓距离排序的最近候选契约，候选仍以层/曝光顺序为主。
- 先核当前 GUI press/worker/reply 选择通路与近边界、图外可达性、过滤和状态重置缺口，再设计 bounded screen-distance 候选与到实际轮廓的距离计算；inside 优先、距离相等稳定排序及层优先仅为建议，须明确冻结规则。Hole、Arc、凹轮廓和变换后的 Block 实例使用真实解析制造几何，不用 AABB/显示细分替代距离。
- 显式核对 visible/selectable、层锁和类型锁的候选过滤。现有锁定仍允许选择而限制编辑；新增“未锁定候选”建议与此规则需统一设计，不能静默改掉已有权限语义。超范围保留既定 blank 行为；Shift/Ctrl 等选择模式、文字组与候选资源预算继续明确。
- 连续点击循环必须确定且稳定，位置超阈值、候选/可见性/权限变化、导航、视口/DPI、文档或工作区修订改变时重置，固定首击锚点避免逐次漂移。异步旧回复/取消不可恢复旧候选。新范围与容差必须是 screen 查询参数，不修改真实几何、世界坐标或 Snap 精度。
- 宏可使用明确 point/range/排序/对象绑定等选择参数；UI 同点连续循环与条件选择是不同动作，不能让回放隐式依赖上一鼠标位置或循环索引。增加图外近/远、洞/弧/Block 旋转镜像、遮挡跨层、锁/类型过滤、候选变更与重复循环/取消回归。


### 3.2 Shift 减选、Ctrl 加选与标准全选命令

- 用户于 2026-10-09 更正此前全选键描述：采用平台常规 command modifier+A，即 Mac ⌘A／Windows Ctrl+A。新 Mac 默认不另加 Ctrl+A 别名。输入框焦点时仅全选文字，IME、录制与模态输入优先；菜单与快捷键走同一全选命令。
- Ctrl 加选、Shift 减选维持物理修饰键语义，Shift 优先，单击及 Window/Crossing 框选都沿现有合约。Mac Command-click 不被改成 Ctrl Add。全选读取完整制造快照，保留可见／Solo／selectable／类型和层分类未锁定过滤、稳定顺序及异步取消，不截断大选区，不产生制造 dirty/Undo。
- 旧快捷键文件只有键位，无默认／自定义来源，不能从“恰等于旧默认”推断用户意图。保留旧 present 条目（含空、自定义及旧 Ctrl+A）和历史跨平台解释；新配置、缺失项及明确恢复默认用 Primary+A，冲突让已有自定义优先。新 Default/Custom 来源仅用于明确区分新默认与用户确认；启动不无条件重写。旧配置可在全选命令行恢复标准默认；原生键生命周期／文本焦点／IME／录制和过滤仍须针对新候选验收。

## 4. 图层色块和分类颜色

- 图层色块上下分割，有分界线；默认上下同色，两个部分都能点击设置。
- 上部控制非 Aperture/Block 图形颜色；下部控制 Aperture/Block 分类颜色。
- 不同 Aperture/Block 分类可各自颜色；下部在分类颜色不同的情况下显示多色图标，点击进入分类设色。已确认是复杂分类设色，不是复制颜色动作。

## 5. Block 创建、嵌套与定义身份

### 5.1 非连续曝光选择创建 Block

- 用户要求允许非连续选择组合；保留同层、可见可选、未锁定约束，不改变制造结果；嵌套是另一任务。
- 当前 UI 和 core 均要求曝光连续。core 将选中成员按原曝光顺序集中到第一个选中位置；中间未选对象会与后续选中对象交换顺序。重叠 Dark/Clear 的交换可能改变覆盖，因此不能直接删除检查。
- 最小建议：保持当前模型/插入位置，对实际发生顺序反转的对象对证明可交换。同极性可交换；异极性覆盖被证明分离可交换。首版使用经数值保护的制造包围盒分离作为充分证明；重叠/相切/未知不等于已证明会变化，只表示不能证明无损。
- 中间未选 Block 需考虑内部曝光；隐藏对象也纳入。不能使用外层实例 Dark、当前像素、面积/周长相同或显示网格替代等价证明。
- 后台检查有预算、取消与修订绑定，最终服务重新验证。无法证明时显示原因和相关中间对象，允许手动扩大选择或取消，不自动纳入/解锁/重排。
- 后续可扩展真实制造覆盖相交证明；“仅保存定义、保留原对象”或保留交错曝光的逻辑分组属于另行显式能力，不是假装当前单槽 Block 能表达任意交错组合。
- 创建按钮应展示具体禁用原因。单个真正 Flash 必然满足连续条件；无至少两个对象限制。需排查空/未确认选择、已有 BlockInstance、源类别/图层权限、快照和显示/活动会话状态。
- 当前 UI 未提前检查目标 Block 类别，而服务会拒绝目标类别隐藏/不可选/锁定；须统一入口与提交检查。不能将这个提交失败原因误当成当前灰按钮的直接原因。

### 5.2 Aperture/Block 嵌套

- 用户希望后续支持嵌套；现有普通 Aperture 是形状定义，不是任意成员容器。RCam Block 可包含引用 Aperture 的 Flash，但类型层面不能包含 BlockInstance；Gerber `%AB` 目前拒绝。
- 须先定义可组合节点、定义/实例关系、合法引用、循环拒绝、递归深度与工作预算、局部/世界变换、曝光顺序，以及编辑/颜色/锁继承。
- 同步设计 `.rcam` schema/API 迁移、引用依赖、Undo/Redo、显示/命中/统计与导出展平；不能只启用 UI 按钮。RCam Block 与 Gerber ApertureBlock 保持清晰区分。

## 6. 真实轮廓编辑点

- 编辑点贴合真实制造轮廓；异形显示全部语义上可编辑的点，含孔洞和复杂轮廓的合法节点。
- 区分外接框变换/尺寸柄、真实轮廓节点及圆弧辅助柄，不把参数尺寸点伪称为顶点。
- 当前长圆角柄使用局部外接框角；多边形尺寸柄位于外接圆半径点。前者不在长圆轮廓上，后者可能不在多边形边上。局部镜像/旋转/缩放/平移已有路径，不能未经截图/实例核对先认定坐标转换错误。
- 当前只有 all-Solid、全 Line 的 Region 提供各边起点；Hole/Arc 边 Region、Macro、Block 内部节点不支持。支持的 Region 没有永久抽稀；50,000 特征预算超限结构化拒绝。显示曲线的 128 段细分不是可编辑节点来源。
- 后续扩展稳定 contour/edge/node 身份、共享端点/闭合更新、孔拓扑、弧控制和定义写时复制。密集节点可视口裁剪/聚类辅助显示，但必须可缩放、候选列表或循环定位到每个可编辑点，不能靠永久抽稀隐藏。
- 保留单步纯预览、释放一次事务、Snap/Grid/Alt、Esc/focus/pointer-loss 取消、f64 与物理像素命中行为。

## 7. 独立 Aperture/Block 定义形状编辑窗口

- 独立定义编辑入口与窗口，复用统一编辑器的制造几何引擎、步骤/预览/校验和 Undo 契约；不复制一套独立形状算法。
- Aperture 常见转换包含方形到内切圆、到多边形，采用图解参数和实时预览。非正方矩形的内切圆口径、多边形内接/外接/方向、孔洞保留及不可表示时的转换策略需明确。
- Block 支持成员形状编辑；成员身份、局部坐标、曝光顺序及引用关系保留。嵌套能力依赖上一阶段模型设计。
- 已确认：默认修改原定义并同步全部引用实例，应用前显示影响数量；保留另建定义仅替换选中对象的选项。一次可撤销，取消不改原定义。
- 默认全量修改时锁定/隐藏引用的权限冲突必须设计；不得暗自忽略锁定、自动解锁或把“同步全部引用”偷偷变成只改可见实例。影响统计包含隐藏引用，不仅当前选择。
- 引用依赖 revision、所有实例派生缓存失效、保存/导出一致性、COW 分支和失败原子性纳入验收。参考图片未验证，不宣称已实现外部软件窗口的全部行为。

## 8. 阵列数量、资源与稳定 UI

- 500000 的建议口径为总阵列格数 `rows × columns`，包含原始 `(0,0)` 位置；不套每轴。此口径已向用户报告，尚待确认；现有模型本来将原始位置计为一格。新增对象为 `(cells−1)×source_object_count`，Block 实例不等于其展开成员数。
- 500000 内不因阵列格数拒绝；超过显示数量与资源预估，可确认继续。不是静默截断，也不是放大后换一个硬 count 门槛。
- 2049 冻结基线还有 10000 总格数硬限和独立的 10000 新增对象拦截，以及整个文档 1000000 对象、2000000 Region 边、64 MiB 保守历史/提交峰值预算和源选择预算。须区分阵列数量策略、结构一致性容量与真实资源预算。
- 数值乘积/ID/内存计费溢出、非法值、无效几何、资源分配失败、原子提交与取消/过期保护保留。不能用确认越过数据一致性错误。
- 按现有事务结构，50 万轻量引用也会超过历史预算。提高专用预算、压缩事务/顺序守卫或其他大阵列策略需另设计；用户尚未确认新预算默认/上限，不能承诺任意复杂阵列成功。
- 大阵列预览须有明确简化提示，不能在 UI 每帧遍历全部格子或展开所有 Block 成员；提交仍按完整模型，不以显示简化截断真实对象。
- 全局生产输入窗口按窗口类型固定宽度，控件固定/最大宽度，统计/校验/异步状态预留固定区域。数字位数、错误文字、统计值不得撑大、跳动或重排；小屏使用视口约束、滚动/截断及完整 tooltip，禁止无限增宽。
- 此布局约束写入项目开发规范并加真实输入/按钮矩形回归；不修改用户审批/custom rules。既有底栏按实际字段有无的单双行规则保留，数值长度不得触发变化。
- 阵列/固定容器独立候选现已冻结为 `4aa552004a56a6e116044a705d3ecbc6bd1a9cf3`，直接父提交 2049；独立源码审查通过，云端 83 项不同 CPU 回归和五项生产 fmt/Mac 目标 check/Clippy 通过，尚未取得 Mac 原生视觉验收或证明 500000 格实际提交成功。候选保留现有真实资源预算；此前按 freeze-only 交回而未推送，本轮已获普通 codex 分支发布授权，发布身份另附逐文件远端核验。本计划提交不包含该实现。

### 8.1 快捷键设置的紧凑布局

- 用户反馈快捷键设置有过多未利用空白，新增独立布局优化项；不混入已冻结阵列候选，不改快捷键映射、配置读写或命令权限。尚无本轮可读截图，不能猜定留白的具体位置或原因。
- 先核现有窗口/内容容器与嵌套 ScrollArea 的实际尺寸、行高、列宽、stretch、提示预留与搜索/录键状态，再确定合理密度。建议明确“名称—当前绑定—修改/重置”列，采用稳定固定/最大宽度与适当行距，小屏滚动和长内容 tooltip；提示占位可收紧，但不靠错误/异步文字撑大或移动关键控件。
- 冲突说明、录键候选/IME/按键释放与取消状态保持清晰可见；长绑定、搜索无结果、等待/失败、录制与导入预览均覆盖实际矩形和可访问性。若源码/本机代表场景仍无法定位，补实际窗口截图再决定布局，不把猜测当成用户指明问题。现有映射、快捷键捕获与配置保护回归须保持通过。

## 9. 全局算术与单位输入

- 适用于全部数值输入，包括移动：`+ - * /`、括号、一元符号、空白及 `.3`。
- 默认采用字段单位；显式 `3mil` 合法。混合单位须量纲安全，不能把长度相乘后默认为长度，不能在面积字段省略必要平方单位处理。
- 除零、非有限结果、未完成表达式、非法单位不能作为 0 或立即提交；保留输入并明确校验，纯预览不修改制造状态。
- 百分比、角度、整数范围分别按字段语义，行列整数不能静默取整。
- 复杂混合裸数表达式的含义尚未确认。建议区分无单位标量与字段单位量，并对有歧义表达式明确提示；不能未经确认给所有裸数隐式附单位导致乘除量纲错误。
- 拟设共享 parser/typed evaluation 与字段 adapter；几何引擎只接收校验后的标准数值。逐键输入、单位切换、IME、Enter/Esc、未执行预览与窗口布局同时回归。

## 10. 大文件保存、细线可见性与撤销预算

### 10.1 保存不阻碍编辑

- 先只读拆解保存快照、serialize、compress、write/flush/replace、全局 busy 和线程边界；分别测量时长、峰值内存和 UI 间隔，不未测先归因于压缩或磁盘。
- 保存操作持有明确版本的不可变快照。保存期间允许继续编辑时，完成结果只建立该保存版本基线；当前版本不同必须保持 dirty，不能旧结果把新编辑标为已保存。
- 同一路径重复保存、排队/取消、关闭工程、工程替换、失败恢复和过期回复须设计；仍保留临时文件、同目录原子替换、覆盖保护及权限/错误处理。
- 保存并发与编辑器跨层一次事务、定义同步修改、Undo/Redo、恢复快照的交互一起验收；不把 UI busy 松开就当作完成异步保存。

### 10.2 大范围细线显示

- 用户要求大范围细线可见性增强。先诊断缩放、逻辑/物理像素、线宽、LOD/合成与性能；不能先认定 shader 或制造线宽错误。
- 任何增强为明确显示层策略，不改制造线宽、轮廓、孔洞、命中真值或 Gerber 导出。视觉增强和真实制造效果可区分；144 Hz 模式与 Retina/普通缩放均测。

### 10.3 可设置撤销预算

- 用户目标为可设置撤销预算；具体默认、上限及内存/磁盘策略未确认。
- 需区分历史条数、实际/保守字节、事务峰值、超大单事务、内部步骤历史与主画布历史；明确自动淘汰旧历史的告知和预算失败的原子性。
- 不以支持大阵列为由静默关闭 Undo、不保留当前步骤或修改全局预算。新预算与兼容迁移需明确决策后实施。

### 10.4 高优先：约 80000 图形选择后的卡顿

- 用户已补精确复现：真实工程仅显示一个层 → 全选约 80000 图形 → 移动鼠标明显持续掉帧；按住拖动有 preview，到目标提交失败且几何不变，具体错误码/文本尚未取得。用户授权此工程用于以后性能测试，真实设计和机器路径仅在私有 Mac 交接中保存；云端只用合成夹具。此报告未在云端新候选上复现或量化，不能把已有 batch-drag/prepare 优化当成缺陷已解决。当前不恢复受限本机性能/崩溃诊断授权，先普通源码定位与测量设计。
- 源码调查入口：`state::refresh_metrics` 每次先枚举选择 ID 构造身份，再做相等判断；身份变化后才按层收集 ID 并调用 `objects_metrics`；`canvas_read::consume_canvas_reply` 复制选择/统计并重建 `gpu::selection_flags`；flags 收集所选 ID HashSet 后扫描 scene IDs。`main` 在选择材料身份变化时派发 `SelectionCenters`；此处 `selection_geometry_identity` 是基于 TaskVersion 与 selection_epoch、与对象数量无关的 O(1) 键，不能与前述枚举 ID 的统计身份混同。另核结果快照、索引/highlight、GPU selected-buffer 上传和真实 prepare/绘制工作。以上是可能开销路径，不是已测因果。
- 进一步普通源码核实：属性面板每帧调用 `drag::editable_selection` 遍历所选对象；`metrics_panel::lines` 在完整统计可用时每帧累加所有指标。flags 重建与完整 View/选择 clone 主要发生回复安装/任务路径，不能未经调用次数测量说成每帧 clone；Arc 快照 clone 本身也不是整份几何复制。优先区分这两类路径，缓存键同时覆盖选择、文档/工作区、层/type 权限、统计结果身份及展示单位。
- 移动容量与预览存在明确源码不一致：`Drag::arm` 不预检数量，而单层 `objects_move` 最终经过 `EditHistory::targets` 的 `MAX_MOVE_OBJECTS=10000`；跨层 `objects_edit_selection` 亦在累计数量超过 10000 时拒绝。这是可用合成单元验证的拒绝路径，不是已取得的真实错误证据；保留失败零修改，不能把既有 64MiB 历史预算当成未经测量的根因。修复应使预览/提交资源要求一致，并在独立事务方案中支持完整选区或明确真实资源拒绝，不静默切成多次 Undo、不截断。
- 将选择查询/构建与结果复制、版本/选择 epoch 更新、面积/周长统计、材料边界/中心计算、高亮/索引、GPU 上传、每帧 UI/paint 与点击 hit 分段记录耗时、分配量/峰值和调用次数。Grip/handles 路径同样核查，当前普通 Grip 入口只接受单对象，不能未经测量就归因于八万握柄创建；区分首次工作与不变选择每帧/每次交互的重复工作。
- 可考虑异步统计、不可变选择/派生结果缓存和有界辅助展示，但必须明确 pending/stale/失败和缓存失效，保持完整选择 ID/顺序及后续命令语义；不截断选区数量、不静默关闭统计或编辑功能来制造流畅结果，不将显示抽样当成真实选择改变。取消、过期回复和文档/权限/场景变更不能安装旧结果。
- 准备约 80000 对象合成夹具及经授权的真实夹具对比，按对象复杂度/Layer/Block/孔/Arc 和选择比例分组。测首次选择、同选区不变帧、连续重新选择、取消和持续鼠标/zoom/pan；记录精确源码、fixture 与适用机器身份，真实数据/私有日志不入公开源码。实际本机实验须遵守当时授权，不改旧门禁或剔除慢样本；本项作为可独立优先诊断，源码实现另提交，不混阵列冻结候选。

### 10.5 多工程打开与 tab 的已确认阶段顺序

- 此项指同时打开多个独立工程，不是把多个 Gerber 导入同一工程。用户已确认顺序：先当前稳定性修复 → tabs 多工程 → 统一编辑器大规模实现；现在预留工程状态隔离，不扩大本轮阵列或性能修复的即时实现。首阶段提供 tabs 与多个工程批量打开，split view/跨工程 transfer 留后续。
- 审核当前单个活动工程/DocumentInfo、ProjectId、worker/service ownership 的边界。每工程独立图层、选择、Undo/Redo、dirty/保存基线、异步任务版本/取消与恢复身份；切 tab 的迟到回复不得安装到另一工程。需定义活动工程命令路由、任务并发/资源预算与逐工程 close/save/未保存保护，再加入多工程批量打开。
- 首阶段不默认承诺 split view、跨工程 copy/move 或共享编辑事务；这些留后续独立定义/身份迁移与权限设计。保存/关闭错误和部分批量打开失败须明确归属，不能以 tab UI 替代工程状态隔离。

## 11. SVG / DXF / PLT 双向交换与最后兼容阶段

### 11.1 当前真实扩展状态

- ADR 0017 和项目开发规范已有多格式架构预留：Gerber 直接进入 Manufacturing Model；SVG/DXF/HP-GL(PLT) 经各自 parser → VectorScene → 显式 Manufacturing Conversion。此预留目前是文档约束，未实现 `VectorScene` 代码类型、格式 registry、三格式 parser 或 exporter trait，不能声称已有可注册插件接口或格式支持。
- 实际 Gerber 导入为 `editor-service/src/workspace.rs` 的 `import_gerber_layers_with_cancel`/内容识别后直接调用 `gerber_io::parse_s1_cancellable`；工程 ZIP 识别只是防止误当 Gerber 导入，不是通用格式分派。
- 实际导出为 `editor-service/src/lib.rs` 的 `export_layer` 与 Gerber writer；公共服务按明确业务方法/命令分派，尚无 SVG/DXF/PLT 格式参数。`editor-core/src/lib.rs` 的 f64 `SemanticDocument` 是制造模型，不是已经实现的通用 VectorScene。
- 已有服务模块边界、自有 DTO、文件权限/取消和原子输出可作为未来复用点；新增格式需真正实现 parser/转换/导出边界和能力声明。现有 `.rcam` 工程保存及 PnP XLSX/TXT/CSV 属于不同业务，不能当作三种通用图形格式已支持的证据。

### 11.2 已纳入计划的能力与待定口径

- SVG、DXF、PLT 双向导入/导出纳入正式后续范围。PLT 暂按 HP-GL；DXF 版本/ASCII 或 binary、PLT 方言/HP-GL/2 子集及实际互通样本尚待确认。本轮不增加依赖、空菜单或未经实现的能力发布。
- 设计可测试的格式识别/分派、各源 parser、VectorScene 与显式制造转换、格式 exporter，以及服务 API/capabilities 的真实扩展点。扩展应进入 GUI/无界面共用服务，不直接修改制造文档，不把 Gerber 强制转换经通用模型。
- 单位、坐标轴/原点、变换、圆弧/Bezier/Spline、线宽和路径闭合必须明确；可精确表示的保持解析曲线，必须拟合时显示误差和范围。不能从 Mesh/像素/当前缩放细分反推输出。
- 填充规则、孔洞、笔/颜色/层映射、stroke/fill 到制造对象、Dark/Clear 转换须显式预览；存在歧义时拒绝或要求用户选择，不能静默按 SVG 或绘图器规则解释 Gerber。
- Block/定义/实例、重复引用、嵌套及变换在目标格式的表示或展平策略明确。导入不支持实体/命令、导出不可表示的对象、属性丢失、外链/字体等均提示实际不支持项，不静默跳过。
- 导入预览报告单位、层/笔映射、对象/曲线数量、转换/拟合与不支持项，确认后一次原子导入；取消/解析错误不留部分工程。
- 每格式独立导出预览、临时文件原子替换和 roundtrip；用独立边界/曲线/孔/层/定义真值及目标工具验证，不仅自身 parser/writer 互证。跨格式不能无损时，准确列出差异并要求显式处理。

### 11.3 批量交换、LN 分层与目标层映射

- 用户已确认：批量导出窗口可勾选多个图层和输出格式；导入窗口提供待导入文件清单、勾选和解析预览，可选择 Gerber LN 作为层名。单文件多个 LN 可以合并一个图层，也可以创建不同图层分别放置对应图形。导入可映射到新建或现有图层。格式、命名、默认映射、覆盖冲突与部分失败策略仍需设计，不能把未实现格式列为成功输出。
- 当前 LN 只保留来源元数据：`gerber-io/src/s1.rs` 将首个绘图前 LN 保存为 `layer_name`，重复或绘图后 LN 放入 `section_names`；`SourceMetadata` 没有 LN 到对象的归属映射，现有导入显示名来自文件名。LN 名字列表不足以实施分层，须在解析实际命令流时记录段落和对象关联，不能按字符串切文件再独立解析。坐标、单位、D-code、极性与 Region 状态可能跨 LN 延续。
- 明确定义缺少 LN 的图形、空或重复 LN、A→B→A 的段落和一个 Region 跨 LN 的处理。默认名称/归并规则须显式预览。合并保留原命令曝光顺序；拆到不同层或导入现有层可能改变 Dark/Clear 合成结果，必须预览冲突并选择处理策略，不能宣称天然无损。定义命名空间、坐标变换、目标层类别/锁定和插入曝光位置须完整校验。
- 导入预览给出 file/LN→new/existing 的映射、图形数量、单位和转换、不支持项与曝光冲突。当前 GUI 是顺序导入、每文件独立提交，停止后已成功文件保留；未来单文件 LN 分组必须原子提交，不能把批次部分成功与单文件半完成混为一谈。解析预览、确认和提交绑定文件内容与文档修订，取消或失败不得留下半个 LN 映射。
- 批量导出先预览 layer×format 的输出列表、命名和路径冲突、不可表示项及覆盖选择，再执行原子单文件输出；总结每项成功/失败/取消及实际路径。批次重试与部分成功口径须明确，不能因一个格式成功而将所有项标记成功。
- 用户已确认 Gerber 增加“合并导出”选项：可分别按图层输出文件，或输出单个 Gerber 并用 LN 区分各图层。预览明确导出模式、有序层列表、LN 名称及空名/重复名处理；具体冲突映射与层顺序规则待设计。SVG/DXF/PLT 使用各自原生层/组/笔机制，不套用 Gerber LN。
- 用户进一步确认所有 Gerber 输出默认 LN=对应图层名称：单层与批量分别输出也适用，合并输出按层切换 LN；宏导出使用相同默认规则。空名、非法字符与重复名的映射/冲突处理仍需设计并可预览，不能静默改名。非 Gerber 使用各格式的层名映射，不写 LN。
- 合并 Gerber 须设计一个合法完整命令流的单位/坐标与光圈/Block 定义命名空间映射、各段局部模态和 Dark/Clear 上下文、元数据及曝光顺序，不能简单拼接多个完整文件。实施前核实标准与目标下游对 LN 的处理；LN 标签不能被当成自动隔离各层合成的承诺。独立图层语义无法保留时，预览说明实际变化/不支持项并明确选择或拒绝，不能静默损失制造结果。
- 与 LN 导入配对验收：多层分别导出及合并→重新导入的 file/LN→层映射、重复/空名、层序、定义冲突、跨段坐标/极性、Dark/Clear 重叠反例、孔和 Region 拓扑。使用独立制造真值及目标下游验证实际支持，不能只有自身 writer/parser 对称成功；单文件输出仍原子且保留覆盖确认。

## 12. 为后续操作宏预留的命令架构

用户已确认以上讨论功能均需为后续操作宏铺垫。这里的 Automation Macro 是编辑操作的录制/回放，与 Gerber ApertureMacro 的光圈几何定义不同。本阶段预留领域命令、参数与执行边界；完整宏编辑器、脚本语言、跨工程身份策略尚未确定，不引入任意代码执行或无限文件/文档权限。

- UI 与领域命令分离：GUI 数值输入、窗口、点击/拾取只生成类型化请求；同一已校验服务命令用于人工操作与未来回放。不能录屏幕坐标、窗口顺序或像素作为制造操作真值。可重放动作定义版本化、可序列化参数，以及输入/输出、前置条件、失败类型和资源预算。
- 选择、对象/定义与目标层需稳定解析或运行时绑定。P0 盘点现有命令/服务方法及所有本计划动作，不宣称已实现通用命令 registry；同项目修订内的稳定 ID 与跨工程解析是不同问题，不能拿旧项目 ID 自动命中新工程。选择表达式、定义原身份、锁定/类型与目标类别均执行原权限校验。
- 数值参数携带显式单位、坐标系/基准和选择作用域；鼠标拾取、中心、镜像目标等在录制时转为可校验点/规则/绑定参数。运行时几何中心必须明确重新计算或冻结输入的选择，不能凭回放时窗口状态隐式解释。
- 固定执行顺序与异步完成契约：一个命令完成并验证输出/修订后才执行下一步；worker 旧回复不推进宏。定义停止/取消、失败保留已完成步骤或整宏回滚的事务策略及 Undo 边界；当前各动作的一次 Undo 保证保留，整宏是否一次 Undo 待设计。资源、错误与确认不得被回放绕过。
- 预留命令成功事件、可录制参数和回放执行接口，区分仅预览/会话草稿、实际提交与不可重放交互。是否记录 Undo/Redo、会话内部步骤及用户取消须先定策略。禁止把任意 UI 事件当成已提交命令。
- 文件导入/导出/保存路径由运行时授权绑定，内容身份、格式能力、不支持项、覆盖与部分失败边界保留；预览/确认不能因“来自宏”静默省略。未知或变更版本的参数拒绝或经明确迁移，不默认猜测。

以下是逐类动作契约起点；P0 必须用真实能力/服务清单补齐逐项命令 ID、版本、支持状态和可重放标记，再进入各功能实现。

## 27. CircuitCAM ASCII 字符生成与字体选择（用户新增，2026-10-10；仅规划）

用户要求优化 RCam 字符生成，使 ASCII 字形、间距、尺寸和笔画效果与 CircuitCAM 的实际 Gerber 参考一致；默认字型使用 ASCII，常用项为 ASCII 和宋体。宋体只按本机实际可用性提供，Mac 未安装时忽略该常用项，不自动安装或用其他字体冒充宋体；其余系统字体由用户在 UI 中自主选择。ASCII 在此指兼容目标的矢量笔画字型，不是把任意系统等宽字体重命名为 ASCII，也不是只有字符编码相同就视为字形一致。

### 27.1 当前实现与差异审计

以冻结产品提交 `4f78908551835cea75e2bb205e27901818a22201` 做只读核对：当前文本草稿已默认选择内置 `builtin:rcam-stroke-v1`，但这是 RCam 自绘 ASCII 中心线字库，尚无 CircuitCAM 几何兼容验收。当前按 `scale=(height_mm-stroke_width_mm)/7` 生成 f64 Line，固定推进量为 `6×scale+tracking_mm`，零行距参数使用 `1.3×height_mm`。系统字体另走字体轮廓生成 Region 路径；Mac 已有字体枚举/搜索/选择，未见宋体独立常用项，Windows 系统字体枚举尚未实现/验收。完整只读记录见 [字符规划审计](CIRCUITCAM_ASCII_TEXT_PLANNING_AUDIT_20261010.md)，不以现有 ASCII 菜单名称宣称兼容完成。

### 27.2 参考核对、已确认纠正与待确认口径

- 用户随后明确“以实际几何为准，0.3*5，字高5mm，线宽0.3mm”。参数格式确认为“线宽×名义字高”，`0.3×5` 即线宽 `0.3 mm`、字高参数 `5 mm`。底排此前明确纠正为 `0.5×10`，即线宽 `0.5 mm`、字高参数 `10 mm`，覆盖错误标注。这是参数含义及参考规格，不新增全局默认尺寸。
- 私有参考的静态审查已报告圆光圈折线笔画与可见 ASCII 覆盖。中排实际圆光圈线宽为 `0.8 mm`，中心线相对上排缩放约 `1.6`；按用户澄清，以实际字形、线宽和间距为准，不强制原错误 `0.5×5` 标注。推导出的名义字高 `8 mm` 尚不是用户明确确认的输入值，须在 CircuitCAM 尺寸标定合同中核验，不能写为“用户确认 0.8×8”。
- 名义 `5`/`10` 不等于所有字符整体包围盒高度，也不等于大写主体高度。须核对笔画节点/笔顺连接、字间推进量、基线、上下伸部、空白、名义尺寸、实际中心线及带圆头/连接的最终轮廓；不能只按总体 bounding box 缩放来模拟字型。
- 参考未覆盖空格推进量、换行、Tab 和非 ASCII，不能由这份样本宣称上述行为已核验；后续以额外获准参考或明确的设计合同补齐。私有参考、字形坐标、原文件/图形及机器信息不进入公开源码或远端分支。
- 中心线偏差与最终轮廓/笔画宽度分开验收，结合参考坐标量化及 RCam writer 量化冻结误差合同。新的量化比较容差仍待评估，不把建议值冒充已确认门槛，不降低既有制造精度或历史证据门槛。
