# Gerber 编辑器 V1：开发设计与验收文档包

版本：1.1 · 日期：2026-09-14 · 语言：中文

## 这份文档包解决什么

将前面的技术讨论落成一套可交给 Codex 分阶段实施的基线，并明确第一版“怎样才算完成”。目标不是仅能查看 Gerber，而是完成真实的打开、选择、编辑、中英文加字、安全保存、重新打开和独立复核。

**当前只有设计与验收规范，没有可运行软件、测试执行器、已核验样本或实测性能。全部 96 个有效验收用例的初始状态均为“未执行”。另有 1 项退役记录，不计入通过数或执行分母。**

## 已确定的第一版边界

采用 Rust + `gerber-parser`／`gerber-types`，建立自有 Gerber 语义层、几何对象与编辑命令；egui／eframe 提供 UI，wgpu 绘制画布。`lib_gerber_edit` 和 `gerber-viewer` 不作为完整编辑能力或输出正确性的前提。

Windows 原生为主开发和发布目标，macOS Apple Silicon 原生为第二必验平台。**不支持 Linux／WSL2，不要求 Linux 核心兼容、构建、测试、CI 或发行包。** 个人辅助工具的选择不扩展产品支持范围；无界面接口也只需 Windows／macOS 验证。

第一版包含多图层、显隐／锁定、缩放／平移、单选／多选／框选、移动／复制／删除／旋转／镜像、数值编辑、撤销／重做、网格／吸附／测距、中英文矢量文字、Gerber 安全另存为和重新打开。

新增的架构要求是：**GUI 与未来脚本共用 `ApplicationService`，无窗口也能完成同一编辑和保存流程。** 第一版要实现可测试的命令／查询 DTO、稳定 ID、版本冲突、原子批次、结构化错误、非交互保存策略和任务接口；以真实无界面集成测试验收。Python／Lua／JavaScript、正式 CLI、脚本控制台和网络控制服务留到后续，当前不必实现。

第一版不要求完整 CAM350 功能，不承诺 CircuitCAM 私有工程、自动开孔识别、圆弧拟合、宏／拼板的任意编辑、Excellon 编辑或正式 SVG／PDF／PNG 导出。范围外输入必须完整识别并安全拒绝，不能漏画后继续保存。

但是，**范围受限不等于可以不支持实际业务文件**。S0 要冻结至少 30 份获准真实样本，其中 10 份业务核心文件必须最终 10/10 编辑并往返成功；样本需要 AM／SR 等功能时，应在 S0 明确扩展设计和用例。

## 建议放进代码仓库的位置

```text
gerber-editor/
├── AGENTS.md                 ← 本包 AGENTS.md
├── README.md                 ← 项目的构建／使用说明，开发时另写
├── docs/
│   ├── DESIGN_V1.md          ← 本包同名文件
│   ├── ACCEPTANCE_V1.md      ← 本包同名文件
│   ├── acceptance_cases.json ← 本包同名文件
│   ├── AUTOMATION_API.md      ← 本包同名文件
│   ├── automation_request_examples.json
│   └── CHANGELOG.md
├── crates/                   ← S0 起创建
├── fixtures/                 ← 开发时创建并核准真实内容
└── evidence/                 ← 每次测试保留真实证据
```

本包的 README 是接入说明，不必直接覆盖已有项目 README。`AGENTS.md` 内使用的是上面的 `docs/` 路径；按此放置后再启动 Codex 开发。已经存在代码时先检查仓库结构与现有功能，避免用模板覆盖实际工作。

## 第一条可以直接交给 Codex 的任务

```text
先阅读 AGENTS.md、docs/DESIGN_V1.md、docs/AUTOMATION_API.md 和 docs/ACCEPTANCE_V1.md。

本次只实施 S0，不一次性开发全部编辑器，也不要生成大量未接线的功能按钮。
关联需求：R01、R05、R06、R17、R18、R19、R20、R21、R22。
参考验收：AT-001～AT-004、AT-085；AT-011、AT-017、AT-018 的最小风险样本；
为AT-086～AT-097确定依赖边界和分阶段实现，不在S0假称全部接口通过。

先检查当前仓库和本机工具链，保留已有有效代码。核对候选依赖实际 API、版本兼容与许可，
锁定工具链和 Cargo.lock。创建最小 Rust 工作区与可运行的 egui/eframe + wgpu 画布，
验证共享 GPU 生命周期、缩放和画布裁剪。

仅配置Windows MSVC与macOS arm64，不新增Linux／WSL2门禁或适配。
在ADR中确定editor-service不依赖窗口/GPU的边界、公共DTO、revision与文件策略；
GUI后续必须调用该服务。不要加载脚本解释器、搭HTTP服务或先做脚本控制台。

建立 Dark→Clear→Dark、带孔光圈叠加线条、跨图层 Clear 的最小合成验证；
可以使用独立定义的几何样本，但不要把此结果宣称为 Gerber 解析／导出已通过。

形成 docs/BASELINE.md、docs/CAPABILITIES.md 和 ADR，记录实际 Windows/macOS
验证情况、性能采样方案、依赖证据及剩余风险。为 REAL30/CORE10 建立 manifest 格式；
真实文件必须获得授权，缺失时明确阻塞，不伪造用户样本。

执行当前阶段实际可执行的构建和测试，提交命令、结果、日志及证据路径。
没有 macOS 或 Windows 实机时记录该项阻塞，不用交叉编译代替 GUI 实测。
先完成 S0 退出检查，再进入 S1。
```

以后每个任务只选择一个阶段内的小闭环，并给出明确的 Rxx／AT-xxx。完整阶段顺序和任务格式见设计第 17 节。

## 从 1.0 文档升级

保留旧版文档／结果归档，用本包更新仓库中的同名设计、用例、JSON 和 AGENTS，并加入接口文档、样例与变更记录。旧 AT-079 退役且编号不复用；新增 AT-085—AT-097，形成 96 个有效用例。

`acceptance_cases.json` 的 `schema_version` 已升为 2：报告程序以 `cases` 为有效集合，以 `retired_cases` 做迁移审计，并读取逐项 `required_platforms`。旧版结果必须明确关联 1.0，不能复制成 1.1 的已通过证据。已有代码先评估服务解耦差距，再增量接入；不要为套目录模板重写已经正确的几何层。

## 验收时怎么用

先冻结依赖、规范、能力范围、实际硬件、样本与阈值。按验收清单建立必要样本和自动执行工具；先做几何／极性／保存安全，再验 GUI 操作、中英文文字、真实无界面接口、性能和双平台，最后完成 CORE10 业务流程。

每条用例记录构建、平台、样本哈希、操作、实际结果、日志／输出／录像和缺陷编号。结果保存在独立运行目录，不将原始规范的“未执行”直接批量替换为“通过”。JSON 中用例数量不等于实际检查次数：同一用例在 Windows／macOS 的结果必须分别记录。

完整 V1 通过条件是：96 个有效用例的所有适用检查（包括接口预留）完成并通过、CORE10 为 10/10、Windows 与 macOS 原生证据齐全、未关闭 B0/B1 缺陷为零。没有相应平台证据时，只能明确标记为对应平台预览版。

## 使用前应特别注意

性能表是拟定的工程门槛，不是 wgpu 的保证，更不是本项目实测成绩；S0 在真实机器上冻结后再执行。不能把“几十万图元必达 60 FPS”当作选型依据。

几何编辑需正确处理曝光顺序、局部孔洞、光圈共享、镜像圆弧、输出量化和元数据；这比外观验收更优先。中文字形必须进入真正的 Gerber 几何，不能只显示为屏幕 Label；普通字体也不自动满足钢网搭桥工艺。

本包不含任何字体文件、用户历史 Gerber 或第三方项目源码。许可与规范资料索引在设计第 21 节；采用实际版本后仍需核对，资料引用不代表软件已经完成兼容性或商业发行审查。
